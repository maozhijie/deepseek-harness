# learnhub 图谱生成（多轮分批构建）

铁律：LLM 只产 YAML，一切入库必须过门禁（schema + 结构检查 + audit）→ 提案 → 人审 → apply。
**绝不一次产全图**：一张像样的课程图有 100-300 个节点，一轮生成必然偷工减料。
正确姿势是像搭积木一样分批多轮构建，每批一个 edit 提案（≤25 个操作），apply 后看清全图再规划下一批。

## 第 0 阶段：范围分析（先想清楚，一轮纯思考，可向用户确认）

动手前先从用户输入里提炼三件事，写进你的构建计划：

- **学习目标**：学完后用户能做什么（最终目标）。
- **用户起点（baseline）**：完全零基 or 已有基础。零依赖的入口单元必须落在 baseline 之内——
  baseline 是零基时，起点必须从最原始、最日常可及的概念起步，不得凭空拔高入口难度。
- **覆盖清单（scope）**：主题下必须出现的子领域 / 大块概念清单。**它是下限不是上限**：
  目标隐含的子领域、必备的常识性概念即使清单没列也要补上，不要只局限于此清单。

## 第 1 阶段：骨架提案（1 轮 gen）

`learnhub_graph_propose`（kind=gen）：完整的 region/block 结构 + **每块 1-2 个入口节点**
（空块会被门禁拒绝）。区块划分按「从易到难」组织，模块间形成连续学习路径。
把结构摘要（区/块数、覆盖思路）讲给用户，同意后 `learnhub_graph_apply`。

## 第 2 阶段：分批展开（多轮 edit，核心）

逐块推进，每批一个 edit 提案（`learnhub_graph_propose` kind=edit，ops 全部 `add_node`，
**每批 ≤25 个操作，宁可多批，不要超长批次**），apply 后立即 `learnhub_graph_analyze`
掌握当前全图（拓扑、层深、连通性），再规划下一批。

- 批内 `pre` 只能引用图中已存在的节点名或本批**更早**创建的节点；引用名必须与图中完全一致。
- 连接两个已有节点 = 对下游节点 `set_pre`（整体替换它的前置全集），没有单独的加边操作。
- 顺序建议：先把当前块的节点补齐，再进下一块；块间衔接在后面批次用 set_pre 补边。

## 构建规范（每一批都要遵守）

【认知粒度】
- 学习单元不一定是原子概念：过度解构原子概念不适合作为人类单次学习行为单元；
  但足够复杂的原子概念可以单独成节点。过于复合的概念必须拆分成多个节点。
- 对每个节点自问：**一个完全零基础的学习者能否在 30 分钟内学会？** 不能 → 补前置或拆解。
  常规单元 5-30 分钟；极困难的综合课最多 60 分钟。
- 难度曲线渐进：从易到难，不能有过突兀的难度跳跃导致不可控的认知负荷；
  相连节点难度跳跃过大 = 中间缺了铺垫单元。

【单元命名】（节点名称质量决定课程质量）
- 大多数 name 是**动作句**：包含 解/求/证明/推导/比较/判定/构造/区分/计算/应用/理解/
  辨析/建立/验证/化简/变形/转化/估计/近似/检验/分类/归纳/抽象/训练 等动作词及其组合——
  人对概念的单次学习行为是一种动作。
- 螺旋式学习合法：同一主题在不同深度以不同视角出现，完整名称不得完全相同；
  允许共享主题关键词，但必须通过动作词或限定语体现认知层级差异。
  正例：「计算简单导数」/「应用导数解决优化问题」/「证明导数中值定理」是合法螺旋；
  「理解导数」/「学习导数」层级不清，禁止。

【依赖契约】
- **充分性**：pre 是完整的直接前置集合——可以存在可选项，但不能少到无法理解后续内容；
  不要为了省事裁剪 pre。
- **收敛**：真实知识是 DAG 不是树——多条前置汇聚到同一节点是常态；连接过少的图大概率
  是认知切分或连接方式有问题。
- 除真正无需基础的入门单元外，pre 不得为空。
- **连通性**：整张图必须是连通结构；有真实依赖关系的地方必须交叉链接。
- 图必须无环；节点名课程内唯一；区/块名不重复。

【覆盖与规模】
- **宁愿节点过多不要过少**；复杂场景的目标节点数通常 **>200**，但优先保证认知合理性。
- scope 清单是下限不是上限（见第 0 阶段）。

【每批上交前自查】
1. 起点基础性：无依赖入口是否真的足够基础？（尤其全图节点数还少、或只有单一入口时——
   宁可先补一层更简单的铺垫单元，不要拿宏大抽象概念当起点。）
2. 覆盖完整性：对照 scope 反思，这批有没有漏掉隐含的子领域？
3. 切分与衔接：这批节点是否足够细？与已有节点的难度衔接是否跳跃？

## 第 3 阶段：审计修复（结束门禁）

全部构建完成后：
1. `learnhub_rebuild`（course 参数指定本课程）跑审计门禁，读 `审计报告.md`。
2. 按 findings 逐条提 edit 修复提案（缺失覆盖 → 把概念改写为动作句 add_node；
   断开组件 → set_pre 接入主结构；孤环/断边 → 修正 pre）。
3. 重新审计直至无 ERROR。
4. **结束条件：audit 基本健康 + scope 覆盖完整**，二者都满足才向用户交付；
   否则继续构建或修复。

## 流程备忘

- 给用户看的阶段性汇报：骨架阶段给结构摘要；展开阶段每 3-5 批汇报一次进度
  （已建节点数 / 当前区）；结束时给审计结论 + 全图统计。
- 大型课程可委派 `subagent_graph_designer` 子代理执行分批展开，父 agent 负责范围分析与交付。
- 用户否决某批提案时按反馈调整后重提，不要跳过人审直接 apply。
