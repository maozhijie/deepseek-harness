# Agent Note: LearnHub per-section style variants and agent tool-surface audit

Status: implemented

[English] | [中文](2026-09-06-learnhub-style-variants-and-tool-surface.zh.md)

## Problem

Style variants were triple-broken against the outline → per-section pipeline: the built-in `课程生成-苏格拉底`/`课程生成-费曼` prompts were wired to a whole-node one-shot path that bypassed the outline, resume, and prev-section coherence injection (the exact origin of the "sections too long" disease treated earlier); worse, the v5 template texts already say "write this one section" while the code used them to generate an entire node in one call — text and usage contradicted each other; and the base `课程生成` template had no consumer left at all. The agent tool surface had real gaps: the agent could not trigger the quiz pipeline (auto-quiz existed only as HTTP), could not launch a whole-course reset (HTTP-only), and could not correct a single bank question (`question_list` omits answers, so the only edit path was rewriting the whole bank blind). The skills still taught five retired v2 tools (`learnhub_check`, `learnhub_grade`, `learnhub_today`, `learnhub_settle`, `learnhub_writeback`) that fail with unknown-tool errors. The graph face had the same disease in four spots: `analyze` shipped only display fields (the agent could see the topology but not any node's est/bloom/difficulty/note values — no data basis for edge-level self-checks), pending proposals were invisible to the agent, `EditOp` had no way to maintain enc component-skill edges on existing graphs, and courses could not be deleted without an HTTP escape. Landing the fix exposed an e2e blind spot: `question_update`'s object parameter lacked an explicit `additionalProperties`, which the dsh-tools compiler rejects and which crashed plugin load — yet the e2e suite never sees it because every step calls the engine directly, bypassing defineTool until dsh boots.

## Decision

Style now lives where it belongs — the section call. Built-ins `课程节生成-苏格拉底`/`课程节生成-费曼` carry the section template plus one style constraint line (guided questions + anchors / analogy → plain language → formal); `generateContent` preloads `课程节生成-<style>` up front (unknown style fails loud before wasting an outline call) and keeps outline, resume, and gates on the default path. The whole-node `课程生成*` built-ins are retired; legacy vault snapshots stay on disk but are never read (manual cleanup). The panel style Select filters the `课程节生成` prefix. The tool surface gains `learnhub_question_generate` (model quiz pipeline, same gate), `learnhub_question_update` (patch merge + revalidate; `{archived:true}` proxies to archive), and `learnhub_course_reset` (shares the `resetCourseChain` orchestration extracted from the HTTP route; immediate return, background topological chain). The graph face gains: a per-node `schema` payload in `analyze` (pre/enc/est/bloom/difficulty/note values; absent in elementsOnly mode), the `set_enc` op (whole-list replace, same shape as the graph YAML, dangling-enc rejected by the simulation gate), the `learnhub_graph_proposals` list tool (pending visibility), and `learnhub_course_delete`. The same round adds the stepwise exploration face (drill into details without pulling the whole graph): `learnhub_graph_node` (single-node detail + transitive prerequisite closure), `learnhub_graph_browse` (region/block-filtered listings), `learnhub_graph_path` (is from a prerequisite of to, plus the BFS shortest chain and closure size), and `learnhub_question_get` (one question in full with the answer — question_list stays answer-free for the answering flow) — 25 tools total. The `patch` parameter gained `additionalProperties: true` (the compiler enforces an explicit boolean on object parameters); e2e now ends with a **plugin-load smoke step**: a mock ctx runs the real bundle's apply, so every tool's schema compiles at registration time — peer packages (dsh-llm/dsh-tools) are junctioned to their workspace package roots (packages/<group> is a group directory, not a package; the step honestly skips when host packages are not built) and stale junction targets are rebuilt automatically. All four skills are de-silted: study no longer mentions retired tools and now teaches the question-generate/update flows; build's intent→tool table and review's schedule reminders point at live tools; graph-optimize cites health/suggestions and set_enc.

## Consequences

Per-style content is strictly better-bounded (one section per call) and style variants now compose with every pipeline feature (resume, prev-section coherence, section shape gate). Users who had picked a style see the same name in the Select — the semantic change is invisible in the UI. Agents can now run the full content lifecycle (generate → quiz → update → reset) without HTTP escapes. Nothing else consumes `resetCourseChain` state, so panel and agent see identical job records.

## Verification

e2e style step asserts the five new built-ins, that the retired `课程生成` kind is not built-in, that the Socratic variant still carries the per-section marker (`## 类型：标题`), on-disk persistence, and unknown-style fail loud; smoke (real vault) checks the same list. The graph step adds a set_enc round-trip to YAML, an analyze-schema field assertion, a dangling-enc rejection, and a proposals listing — which caught the schema initially shipping `encOf` tuples instead of the declared `{node,w}` objects. The exploration tools have their own assertions: node detail fields/succ/enc, browse counts, the path chain plus its unrelated reverse, and a full-question read with unknown-qid fail loud (the first draft asserted against a node that the rename-linkage step had renamed away — a live sample of bank migration semantics). The load smoke has a negative proof: removing `additionalProperties` makes the smoke FAIL with the exact dsh-boot crash message, and restoring it turns the suite green. `npm run build`, `npm run check`, UI `tsc --noEmit`, e2e all green.

## Rejected alternatives

- **Keep whole-node one-shot as a parallel style path** — two generation semantics for one node invites drift; the per-section path already enforces shape gates and coherence that one-shot can only approximate.
- **Style as an injected hint paragraph into the shared section template** — an extra indirection the user cannot see or edit in one place; a full per-style template file matches the existing editable-prompt mechanism exactly.
- **A generic `learnhub_api` passthrough tool instead of three named tools** — named tools keep descriptions doing the teaching (when to confirm, what the patch fields are); a passthrough would smuggle HTTP semantics into the agent surface.
